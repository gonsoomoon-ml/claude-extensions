Anthropic이 7월 블로그에 낸 컨텍스트 엔지니어링 새 규칙과, 저희가 AWS 블로그에 쓴 에이전트 Deep Insight의 4계층 컨텍스트 엔지니어링. 둘 다 “컨텍스트(AI의 작업 기억)에 무엇을 넣을지”를 다룬다. 나란히 놓고 대입해 봤다.

Anthropic 새 규칙이란
최신 모델은 프롬프트 80%를 지워도 성능 그대로.
그래서 프롬프트를 이렇게 바꾸라고 한다
이전엔지금은
①규칙을 빼곡히 적기→판단 기준만 주기
②예시를 잔뜩 넣기→도구·형식을 설계
③정보를 전부 미리→필요할 때만 불러오기
④같은 말을 반복→도구 설명은 한 줄
⑤메모리를 사람이 관리→모델이 스스로 기록
⑥짧은 스펙→코드·화면·채점 기준 첨부
Deep Insight 4계층이란
컨텍스트가 넘치지 않게 하는 장치 4개.
그중 2계층이 프롬프트다
1계층 컨텍스트를 나눈다 (멀티 에이전트 격리)
에이전트마다 컨텍스트 따로 · 코더는 25K 토큰 이내
2계층 짧게 답하게 한다 (프롬프트 제어)
프롬프트로 길이·형식·규칙 지정 · 답은 1,500토큰 이내
3계층 무거운 건 파일로 (파일 외부화)
코드·결과는 파일에, 컨텍스트엔 위치만 · 95% 절감
4계층 따로 검증한다 (검증·안전장치)
다른 에이전트가 숫자를 다시 계산 · 오차 0.01까지

그럼 Deep Insight 4계층은 Anthropic 새 규칙에도 유효할까?

답: 3계층은 새 규칙에서도 유효하고, 프롬프트(2계층)는 더 다듬을 수 있다

①②③⑥은 위 패널의 규칙 번호
Anthropic이 줄인 프롬프트의 예
9,100자 → 한 줄
‘할 일 목록’ 도구의 설명문. 예시·목록을 빼고 한 줄 설명 + 상태값 3개 + 규칙 하나만 남김 (규칙 ④)
Deep Insight가 파일로 옮긴 예
20K → 500토큰
항상 넣는 양: 스킬(분석 절차) 설명서 전체 대신 목록만 (97%↓). 필요한 스킬은 그때 3K씩 따로 불러옴 (3계층)

모델이 똑똑해져도 컨텍스트 엔지니어링은 남고,
프롬프트만 모델에 맞춰 다듬는다

4계층의 코드와 수치는 AWS 블로그 글에 (링크는 본문)
